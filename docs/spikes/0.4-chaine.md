# Spike 0.4 — Chaîne complète voix → texte → modèle → voix

**Statut** : la chaîne fonctionne de bout en bout sur une question ; il reste à
**mesurer la latence de dialogue sur un PC Windows, AMD et NVIDIA**. Dans un
conteneur sans GPU, elle est de 25 s : sans intérêt pour le jeu, mais la preuve
que les quatre briques s'emboîtent.

## Ce que fait le spike

`spike-chaine` charge Whisper, une voix Piper et llama-server, puis :

1. **Question** : l'intervieweur (LLM) formule une question sur le thème, lue
   par la synthèse vocale.
2. **Réponse** : le joueur répond au micro (Entrée pour parler, Entrée pour
   finir) ; ou bien `--reponse-wav` fournit la réponse, pour mesurer sans parler.
3. **Relance** : la réponse est transcrite (Whisper), l'intervieweur relance
   (LLM), la relance est lue. Le temps entre la fin de la réponse et la première
   phrase prête à être jouée est la **latence de dialogue**, ce que le joueur
   attend.
4. **Juge** : la réponse est notée (LLM, JSON imposé), après la relance.

Le juge passe en dernier exprès : dans le jeu, la relance parlée occupe le
joueur pendant que le juge travaille, et le score peut s'afficher ensuite.

Le code vient des crates `bullitik-voice` (Whisper, Piper) et `bullitik-llm`
(llama-server, contenus), partagées avec les spikes 0.1 à 0.3 et réutilisables
par le jeu.

## Lancer

| Où | Commande |
| --- | --- |
| Devcontainer, au micro | `cargo run --release -p spike-chaine` |
| Sans parler, réponse dans le WAV de test | `cargo run --release -p spike-chaine -- --reponse-wav crates/voice/testdata/phrase.wav --no-play` |
| Windows natif | `.\spike-chaine.exe`, voir [windows.md](windows.md) ; `mesurer.ps1` le lance avec le WAV de test |

Options : `--theme`, `--voice` (défaut `upmc-pierre`, la plus intelligible au
spike 0.2, en attendant le choix), `--cpu`, `--stt-model`, `--model`.

## Résultats

Conteneur cloud, 4 vCPU, **sans GPU**, Whisper small, Ministral 3 8B ; la
réponse est le WAV de test (« Qui est responsable de la baisse du pouvoir
d'achat ? Je crois que la vraie question, c'est celle de la confiance que les
Français accordent à leurs institutions. »), une esquive discrète.

| Étape | Temps (CPU) |
| --- | --- |
| Question : texte du LLM | 8,6 s |
| Question : 1re phrase de voix | 0,5 s |
| Transcription (7,3 s de parole) | 7,0 s |
| Relance : texte du LLM | 16,9 s |
| Relance : 1re phrase de voix | 0,4 s |
| **Latence de dialogue** | **24,6 s** |
| Juge (après la relance) | 37,9 s |

Ce que l'on voit sur un exemple :

- **Relance** : « Vous éludez la question : l'INSEE a chiffré la baisse du
  pouvoir d'achat en 2022. Cette baisse vient-elle des prix, des revenus, ou
  des deux ? Répondez simplement. » Elle est juste : elle nomme l'esquive et
  reformule.
- **Juge** : n'a pas répondu, pertinence 7, discrétion 6, « remettre en cause
  la question », score 42. Il repère le recentrage sur « la vraie question ».
- **Question** : l'intervieweur cite encore des chiffres de l'INSEE inventés
  (« −1,2 % en 2022 ») et ajoute « Oui, non, ou les deux ? Répondez
  clairement. » Son prompt est à reprendre au lot 1 (#14).

## Ce que l'on en tire

- La chaîne tient : quatre briques, deux sur GPU (Whisper, LLM) et une sur CPU
  (Piper), dans un même processus plus llama-server.
- Sur CPU, la latence est dominée par le LLM (relance) puis par Whisper. La
  voix, elle, est négligeable (moins de 0,5 s pour la 1re phrase).
- Pistes si la latence GPU déçoit : réduire `max_tokens` de la relance,
  diffuser le texte du LLM en flux (streaming) et lire la première phrase dès
  qu'elle est complète, réduire le contexte audio de Whisper.

## Verdict

En attente des mesures sur PC. Critère proposé, à valider : latence de dialogue
sous 3 s sur GPU.
